# gemini response

Создать свой MCP-мост, который даст агенту доступ к **99% возможностей редактора Figma**, не просто возможно в теории — это реализуется буквально за пару вечеров и упирается всего в 200–300 строк базового кода. 

Причина, по которой `html.to.figma` (он же `html.to.design`) может собрать на холсте сложнейший интерфейс, а популярные MCP-серверы с GitHub спотыкаются на базовом Auto Layout, кроется в архитектуре API самой Фигмы и в том, как авторы опенсорсных решений проектируют свои тулы.

---

## Почему готовые MCP-мосты с GitHub такие урезанные

У Figma есть два совершенно разных API:
1. **Figma REST API (внешний HTTP):** работает через облако без открытого клиента, но в плане структуры макета он работает **только на чтение**. Через него нельзя создавать фреймы, менять цвета или настраивать Auto Layout.
2. **Figma Plugin API (внутренний `figma.*`):** работает внутри запущенного клиента Figma. Именно его использует `html.to.figma`. У этого API есть полный доступ к холсту: создание любых нод, векторных сетей (`VectorNetwork`), булевых операций, привязка переменных (Variables), настройка Auto Layout, эффектов, компонентов, вариантов и даже связей прототипирования.

Чтобы дать внешнему ИИ-агенту доступ к записи на холст, любой неофициальный мост обязан работать по цепочке: **MCP Server — локальный WebSocket — запущенный плагин внутри Figma**. 

Проблема в том, что авторы большинства существующих решений (например, `Figma-MCP-Write-Bridge` или `figma-mcp-bridge`) попали в **«ловушку ручных оберток»**:
* Они вручную описывают отдельные MCP-инструменты под каждое действие: `create_frame`, `set_fill`, `set_corner_radius`, `set_opacity`.
* В Figma Plugin API сотни свойств и методов. Как только агенту нужно выставить `layoutSizingHorizontal = 'FILL'`, привязать токен к отступу, загрузить нестандартный шрифт или сделать сложную маску — нужной «обертки» в MCP просто не оказывается.
* **Проблема атомарности и задержек:** чтобы нарисовать одну карточку товара через такие примитивные тулы, агенту приходится делать 30–50 последовательных вызовов MCP. Это сжигает контекст, занимает минуты и постоянно ломает верстку.

---

## Что с официальным MCP от Figma

У официального решения Figma есть важный нюанс, о котором многие не знают. Сейчас Figma развивает два варианта своего MCP:
* **Desktop MCP Server (локальный):** работает только на чтение и действительно жестко требует платного места (Dev или Full seat на платных тарифах).
* **Remote MCP Server (`[https://mcp.figma.com/mcp](https://mcp.figma.com/mcp)`):** в нем недавно появилась функция **Write to Canvas** (прямая запись нативноего контента на холст) и генерация макетов из живого UI браузера. Пока функция находится в открытой бете, сама генерация бесплатна (хотя для записи за пределами черновиков нужен Full seat), но Figma уже официально заявила, что после беты запись на холст станет платной по модели usage-based (оплата за использование).

Поэтому зависимость от официального MCP в долгосрочной перспективе действительно означает привязку к их биллингу и лимитам.

---

## Как спроектировать свой MCP со 100% доступом к холсту

Плагин в Figma состоит из двух изолированных частей: **Главного потока (`code.js`)**, где есть объект `figma.*`, но нет доступа в интернет, и **UI-окна (`ui.html` внутри `iframe`)**, где нет прямого доступа к холсту, но работают обычные браузерные API и `WebSocket`. Они общаются друг с другом через `postMessage`.

Чтобы твой агент мог делать в Figma **абсолютно всё**, не нужно писать 200 мелких инструментов. Достаточно дать ему **три правильных механизма**:

### 1. Прямое исполнение кода в песочнице (`execute_plugin_code`)
Вместо того чтобы ограничивать агента набором функций `create_rectangle`, дай ему один универсальный инструмент — отправку строки с JS-кодом, который выполняется внутри главного потока плагина через `AsyncFunction('figma', code)`.
* Современные LLM прекрасно знают документацию `@figma/plugin-typings`.
* Агент сам напишет скрипт, который за один проход загрузит шрифт через `await figma.loadFontAsync(...)`, создаст всю иерархию фреймов, настроит Auto Layout, привяжет локальные переменные и вернет JSON с `id` созданных элементов.
* Только недавно на GitHub начали появляться первые проекты, использующие этот подход (например, минималистичный `Zfinix/figma-bridge`, где тул `execute` пробрасывает произвольный код прямо в Plugin API, или `southleft/figma-console-mcp` для дизайн-систем).

### 2. Декларативный мост «HTML/Tailwind в Auto Layout»
Почему `html.to.figma` выдает такой точный результат? Потому что браузерный движок уже умеет идеально считать Flexbox и Grid, а языковые модели в десятки раз лучше пишут HTML/Tailwind, чем высчитывают координаты и свойства нод Фигмы.
* Внутри `ui.html` твоего плагина есть полноценный браузерный DOM.
* Если ты добавишь в свой MCP инструмент `render_html_to_figma(html, css)`, агент сможет просто сгенерировать верстку на Tailwind, отправить её в невидимый `iframe` плагина, а скрипт внутри плагина пройдет по `getBoundingClientRect()` и `getComputedStyle()` каждого DOM-узла и мгновенно сконвертирует их в нативные фреймы Figma с Auto Layout (именно так под капотом устроены open-source библиотеки вроде `html-to-figma` / `svg-to-figma`).

### 3. Визуальная обратная связь (Self-Correction Loop)
Даже с полным API агент остается «слепым» и часто ошибается с режимами `HUG` и `FILL`, из-за чего текст вылезает за границы кнопки.
* Включи в ответ твоего MCP автоматический вызов `await node.exportAsync({ format: 'PNG', constraint: { type: 'SCALE', value: 1 } })`.
* Когда агент сразу после изменения получает обратно не только JSON-дерево, но и base64-скриншот получившегося фрейма, мультимодальная модель сама видит поехавшую верстку и исправляет её вторым запросом.

> **Единственные технические ограничения (около 1%):** плагин работает только тогда, когда целевой файл открыт в десктопном приложении Figma (или в браузере) и в нем запущен твой плагин в режиме разработки. Также через Plugin API нельзя управлять настройками аккаунта/команды и кликать по системным меню самого интерфейса Figma вне документа. Всё, что находится внутри самого холста, доступно полностью.

## Стоит ли создавать такой проект?

* **Если делать очередной набор из 30 базовых тулов (`create_rect`, `set_color`) — не стоит.** На GitHub по тегу `figma-mcp` уже больше сотни репозиториев, и почти все они клонируют этот тупиковый подход.
* **Если сделать гибридный «комбайн» (HTML/JSX-рендерер + полный JS REPL + авто-скриншоты) — однозначно да.**
  1. **Для себя:** базовая связка «MCP Server на Bun/Node.js + WebSocket + плагин с `eval` и скриншотами» пишется за выходные и сразу закрывает все потребности без подписок и лимитов.
  2. **Для Open Source / портфолио:** сейчас огромная дыра между примитивными рисовальщиками квадратиков по WebSocket и платными проприетарными решениями. Open-source MCP, который принимает от агента чистый HTML/Tailwind (или компактный JSX-подобный DSL), превращает его в чистый Auto Layout с привязкой к локальным токенам файла и позволяет докручивать детали прямыми вызовами `figma.*`, мгновенно соберет вокруг себя комьюнити.

Для базового контекста по тому, как сама платформа позиционирует стандарт и какие сценарии закладывает в свою официальную интеграцию, можно посмотреть обзор [What is the Figma MCP server?](https://www.youtube.com/watch?v=s7BZz03icnY). Это короткое видео от команды Figma наглядно показывает базовую механику работы их штатного MCP-сервера, от которой можно оттолкнуться при проектировании собственного полнофункционального моста.

# gemini response

Коротко по обоим пунктам — что реально сделать и где лежат жесткие ограничения безопасности самой Фигмы:

### 1. Сложные эффекты (Glass, Noise, Texture и шейдеры) — **Да, на 100%**

Здесь HTML/CSS-конвертер нужен только для черновой геометрии и Auto Layout, а эффекты добиваются двумя путями:

* **Нативные эффекты Figma (`Glass`, `Noise`, `Texture`, `Progressive Blur`):** они уже официально доступны в `Figma Plugin API` через массив `node.effects`. Твой агент может либо выставлять их напрямую через JS-песочницу (`execute_plugin_code`), либо ты можешь добавить в свой HTML-парсер кастомные атрибуты (например, `data-figma-effect="glass"`), которые плагин при конвертации превратит в нативный эффект стекла Фигмы.
* **Шейдеры (WebGL / GLSL):** сама Фигма не хранит живые шейдеры на холсте — все шейдерные плагины в комьюнити рендерят картинку в скрытом браузерном окне и накладывают её как заливку. Так как у твоего плагина есть `ui.html` (полноценный браузерный `iframe` с доступом к WebGL и `canvas`), агент может написать любой GLSL-шейдер, отрендерить его в `iframe`, забрать байты и через `figma.createImage()` мгновенно положить на ноду как текстуру.

---

### 2. Запуск других плагинов и поиск в Community — **Напрямую нет, но есть обходной путь лучше**

* **Запускать чужие плагины из своего нельзя:** в Figma действует жесткое правило песочницы — *«в один момент времени может работать только один плагин»*. Как только запускается сторонний плагин, Фигма принудительно убивает процесс твоего MCP-моста. Управлять UI чужого плагина через API тоже запрещено (это можно сделать только внешним кликером через Computer Use / AppleScript, но это костыль).
* **Почему это не проблема:** 95% плагинов в Figma — это просто JS-скрипты поверх того же `figma.*` API (генераторы сеток, иконок, градиентов, мокапов). Вместо того чтобы вызывать чужой плагин, твой MCP-сервер может:
  1. **Использовать внешние API и npm-пакеты напрямую:** сервер крутится локально на Node.js/Bun, поэтому агент может сам тянуть иконки (Iconify/Lucide), 3D/шейдеры, иллюстрации или готовые SVG из сети и вставлять их через `figma.createNodeFromSvg()`.
  2. **Искать и подтягивать ассеты из библиотек и Community:** через `figma.teamLibrary` и `figma.importComponentByKeyAsync()` агент может импортировать готовые компоненты по ключу, а поиск по открытым файлам Figma Community можно реализовать на стороне MCP-сервера через обычный веб-скрейпинг/поиск и REST API Фигмы (вытаскивая нужные ноды из публичных комьюнити-файлов и копируя их в проект пользователя).

**Идея для твоего Open Source проекта:** вместо попытки запускать чужие закрытые плагины сделай в своем MCP **систему текстовых «скиллов» или пресетов** (например, готовые промпт-рецепты и функции для генерации сложного стекла, 3D-шейдеров, сеток и мокапов). Для пользователей это заменит десяток платных плагинов одной командой агенту.
